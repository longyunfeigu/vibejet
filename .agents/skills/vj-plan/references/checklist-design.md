# 验收清单怎么写

验收清单写一次用三次：用户开工前审它；AI 写代码时先把每条变成测试；做完后自动项由 AI 跑、人工项交给用户亲手试。
所以每条既要让没参加讨论的人看懂，又要具体到能写成测试。

## 每条怎么写

| 列 | 写什么 |
|----|--------|
| 编号 | `A1`、`A2`…，全文唯一，`vj-work` 开工时按它写"验收对应的测试" |
| 要保证什么 | 一句产品语言：用户做什么 → 系统保证什么。不写测试名、状态码、`data-testid`、表名——那些由 `vj-work` 写进测试 |
| 怎么查 | `自动测试`（单元 / 接口 / 数据库断言）、`浏览器`（打开页面点、截图看）、`人工`（只能人在真实环境里试，如真实模型超时、真实成本） |
| 对应 PRD | 引用的 PRD 行为规则编号，如 `R2`；没有写 `—` |

不用"正确 / 合理 / 正常显示"这类词：写不出可判断的结果，就是还没想清楚。

## 先按场景派生，再写

按用户会遇到的场景分组（如"一句话记下一餐""AI 出错时""改错了"），每组用合适的方法找候选，别从通用清单凑：

| 场景里有什么 | 方法 | 得到的检查 |
|--------------|------|------------|
| 输入字段 | 等价类：每种无效输入一类 | 每类非法输入怎么被拒绝 |
| 数值 / 长度 / 日期范围 | 边界值：min-1 / min / max / max+1 | 合法边界能过，越界被拒 |
| 多个条件决定结果 | 决策表 | 每条规则一项 |
| 有状态的东西 | 状态 × 事件 | 合法转换，加至少一个非法转换 |
| 一段用户流程 | 主流程 / 备选 / 异常走一遍 | 备选和异常各成一项 |

## 必须覆盖的

- **PRD 行为规则**：PRD §12 里和这块相关的每条规则至少一项。数据归属、权限、隐私这类每个功能都要守的
  规则，放在最前面一组"全局"，配一个覆盖这块所有接口 / 数据表的测试，不在每个场景里重复写。
- **PRD 例子表**：§12 例子表里和这块相关的每一句都要出现在某一项里，原话照抄；同一类的几句可以写进同一项
  （如"火锅 / 三明治 / 鸡胸肉沙拉 → 追问"），不必一句一项。
- **调用大模型的能力**（来自对照实验：只测"模型正常返回"的计划漏了下面几项）：
  - 模型超时、报错、未配置时的降级路径；
  - 模型返回格式不合法或对不上业务数据时，不写入、转兜底；
  - 模型给出的数字（热量、价格、分数）不采用，由系统算；
  - 发给模型的请求不带用户身份，日志不存用户原话全文；
  - 至少一项`人工`：用真实模型试一次超时或故障；
  - PRD 有成本约束时，每次调用记录用量，能按用户统计。
- **界面**：计划里写到的每条交互路径（主流程、备选、出错）至少一项，每个页面的加载、空、出错、成功、无权限状态
  各一项，外加一项`浏览器`截图检查（手机宽度下不重叠、主操作看得见）。

一个场景超过约 8 项，或整份清单超过约 40 项，说明这块太大，回去把计划拆成两份。
