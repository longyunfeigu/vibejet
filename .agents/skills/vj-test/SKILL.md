# vj-test — 一份计划的跨层 E2E 测试

`vj-work` 的测试只覆盖单个任务；跨任务的端到端流程（如"前端登录 → 会话落 DB →
`/me` 返回用户"）要在实现完成后补。本 skill 全自动跑完，人只读报告，不设人工关卡。

## 原则

- **绿不等于有效。** 人不做手工验证，所以测试是唯一的安全网：每个高优先级的代码级测试都要过
  变异自检（故意改坏目标行为 → 确认测试变红 → 丢弃改动）。改坏了还是绿的测试测不到东西，标 INVALID。
- **断言真实状态**：DB 行、缓存条目、API 信封、前端渲染都断言真值，跨层不 mock。
- **只做跨任务的 E2E**，不重复 `vj-work` 已写的任务级测试；按风险只覆盖高优先级场景，
  不测框架、库或 DB 内部，不追覆盖率。
- **前端用 `web-access` 驱动真实浏览器**，不引入 Playwright/Puppeteer 依赖。

## 输入与产物

`vj-test <计划文件>`，或空参取 `docs/work/plans/` 下状态为 `done` / `in-progress` 的最新计划。
测试计划和报告追加进同一份计划文件（`## 8. 跨层测试`），截图放 `docs/work/plans/{date}-{slug}.evidence/{scenario}-ok.png`，
以及测试代码。

## Phase 1：探基建、起应用

并行探测，一次汇总可用和降级清单，中途不停下：

| 基建 | 探测 | 缺失时 |
|------|------|--------|
| 测试 DB | 建测试连接或临时库 | 后端层降级，报告写"后端 DB 测试未覆盖" |
| API 测试客户端 | httpx / FastAPI TestClient | 同上 |
| 缓存 | 项目使用时检测连接 | 跳过缓存断言，报告写"缓存层未覆盖" |
| 前端驱动 | 用 `invoke_skill` 加载 `web-access`（全局 skill，不按项目路径猜） | 前端降级，报告写"前端未自动覆盖" |

前端可用时启动后端和前端 dev server（自动探测 `pnpm dev` / `uv run`），记录 URL，测完关闭。
起不来就换启动命令重试一次，仍失败则前端降级并写明原因。任何降级都要写进报告，不能悄悄不测。

## Phase 2：风险驱动规划

读计划的验收清单和关键设计，列出单个任务写不出的跨层场景。
每个场景写清：触发 → 经过哪些层 → 每层断言什么真实状态。按风险排序（破坏性、数据正确性、安全、
核心流程优先），写进计划文件的 `## 8. 跨层测试`。

## Phase 3：写测试、跑测试

- 后端：pytest + httpx/TestClient，断言 API 信封、DB 行和缓存。
- 前端：用 `web-access` 走完整用户流程并做显式 UI 断言（例如提交登录后断言页面显示用户名），
  不能只截图。每条成功流程把截图写到计划旁的 `.evidence/{scenario}-ok.png`（`browser` 能力直接落盘，
  只返回字节时用 `write_file`），再用 `test -s` 确认文件存在且非空。
- 失败时先判断是测试写错还是实现 bug：验收清单明确要求的行为没做到是实现 bug，改实现；清单没说的
  或断言写错了，改测试。不要为了变绿去弱化清单要求的行为。最多修 3 轮，仍红就停下，在报告里列
  未修复项和原因，交给人。
- 改实现代码是本 skill 影响面最大的动作：只改验收清单明确要求的行为；commit 策略允许时每次实现改动
  单独 commit，不和测试改动混在一起，否则在报告里单列这些改动。

## Phase 4：变异自检（只做代码级测试）

对每个高优先级后端测试：定位它断言的被测代码行（返回值、条件分支、状态写入）→ 故意改坏 →
只跑这一条（`uv run pytest {file}::{test} -x`）→ 变红是 VALID，仍绿是 INVALID。

改坏代码只在隔离 worktree 里做，用完丢弃，主分支不受影响。测试多时用 `spawn_agent` +
`isolated_worktree` 每条一个任务并行跑，返回
`{test, mutated_line, result: RED|GREEN, verdict: VALID|INVALID}`；只有几条时在一个隔离 worktree 里顺序做。

前端 E2E 不做变异（成本高），信任依据是成功截图加显式 UI 断言，报告里要注明这一点，避免给人前端也"验过"的错觉。

## Phase 5：报告

在 `## 8. 跨层测试` 下写报告，让不跑测试的人也心里有底：每层覆盖了什么、对应哪些验收项；按风险覆盖了哪些、
砍了哪些及原因；变异自检结果（哪些测试证明能抓 bug、哪些无效建议删除）；前端截图链接；
未覆盖项及原因。
