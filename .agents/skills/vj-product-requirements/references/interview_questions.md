# 采访题库

`create` / `update` 模式第 1 步用（两个押注问题在第 3 步选方向时用）。目标是把只有用户知道的事问出来；网上查得到的（竞品功能、行业数据）
不问用户，留给第 2 步调研。

## 规则

- 不问显而易见的问题。好问题的标准：答案会改变产品方向、范围或取舍。"要不要登录""喜欢什么颜色"不算。
- 用 `ask_user` 批量问，每轮最多 4 题。每题给 2-4 个选项，第一个是推荐默认值并写明理由；用户可以自由作答。
- 每轮结束先把答案收敛成能写进 PRD 的一句陈述，再决定下一轮问什么。
- 已经被用户或现有 PRD 回答过的不重复问。
- 用户明确说不知道时，不要逼用户猜：记为 `[未验证假设]`，写进 §8，并给出验证方式。

## 先判断阶段

| 阶段 | 信号 | 调研默认 |
|------|------|----------|
| 新产品 0→1 | 还没有产品、用户或付费流程 | light |
| 已有产品加功能 | 已有产品和用户 | none |
| 内部工具 | 团队内部流程 | none |
| 纯技术债 / 合规 | 不直接改变用户行为 | none |

范围模式默认 Standard；用户要最小版本用 Lightweight，战略性或高风险工作用 Deep。

## 五个必问（用户要求直接出草稿时也要问）

前三个在采访时问；后两个是押注问题，等用户在第 3 步选方向时再问——看到原型之前答不出来。

| 问题 | 为什么必问 | 写进 |
|------|------------|------|
| **证据**：这个问题真的发生过吗？用户做过什么具体的事（付过钱、搭过手工流程、抱怨过、放弃过）？ | 区分"觉得有用"和"已经造成成本" | §1、§8 |
| **现在怎么应付**：没有这个产品时，用户靠什么凑合？代价是什么（时间、错误、放弃）？ | 决定问题陈述和成功指标 | §1、§1.1 |
| **最小但有价值的版本**：如果只能保留一个场景端到端跑通，是哪一个？哪些只是方案偏好？ | 决定 MVP、非目标和延后能力 | §4、§9、§11 |
| **为什么选我们**：同样的需求，用户为什么不用现有方案？我们押注哪一点？ | 回答不了就是在做同类功能清单 | §5.1 |
| **第二次为什么回来**：用户用过一次之后，什么让用户再打开？ | 很多产品死在第二周，不是第一天 | §5.2 |

## 按需追问

- **用户**：核心用户是谁、在什么场景下用、多久用一次？谁会被影响？→ §3
- **流程**：完成核心任务的主路径是什么？最容易失败或流失的是哪一步？→ §1.2、§4
- **边界**：哪些数据敏感、谁能看谁能改？有什么合规、性能或外部依赖限制？→ §6、§10
- **质量细节**：哪些异常、空状态、失败状态必须处理？只能保留 2-3 个细节时选哪几个？→ §12
- **持久性**（仅 Deep）：12 个月内什么变化会让这个需求失效？→ §10

## 非目标

写 PRD 前一定问一次：这次明确不解决什么？可以是人群、流程步骤、平台、权限、集成、报表、自动化或后续版本的能力。→ §9
